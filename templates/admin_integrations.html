Notification delegation

Instead of this app building its own Discord bot or email sender, a new request and a request status change are POSTed to status-portal, which delivers them however it's already configured to. This URL and key are issued by status-portal, in the opposite direction from the health key above - keep them separate.

The server-to-server address this app's backend can reach directly - usually the LAN one, not necessarily the same URL shown to visitors above.

Leave the URL or key blank to disable delegation entirely - nothing is sent, and nothing breaks, same as before this was configured. Unchecking one of the events above disables just that one; the other keeps working.

Test it

Sends one real notification through the chain above right now, so you find out immediately if it's broken instead of only when a real request comes in.
